# Features that a static site can't do by itself

A static site is a set of finished files. Anything that needs a server at the moment a visitor does something (send a form, search, log in, buy) needs a replacement. For each item the inventory flags, check on the live site whether it is really used (site-wide flags often only mean the theme loads a plugin's files everywhere), then present the recommended option first.

**Simplest first.** For every feature, first ask whether a link, an e-mail address, a phone number or nothing at all does the job, and recommend that unless the feature clearly earns its keep. Owners can't judge what keeping a feature costs; tell them in their terms: days of setup, monthly fees, a new entry in the privacy policy, spam, someone who has to notice when it stops working. A web developer would say "drop the form, let people write an e-mail"; say it too, and explain why.

Legal remarks below (privacy, cookies) are pointers, not legal advice; tell the owner to confirm with whoever handles their privacy policy.

## Contents
- Usually easy: sliders, galleries, video, maps, fonts, downloads, archives, feeds, sitemaps
- Needs a small service: forms, newsletter, search, booking, analytics
- Usually dropped: comments, social feeds, cookie banner, captcha
- Not static: shop, members area, password-protected pages
- Structural: page builders, multilingual sites, events

## Usually easy

| Feature | Recommended | Alternatives | Notes |
|---|---|---|---|
| **Slider / carousel** (Revolution, LayerSlider, Master Slider, Smart Slider, Swiper) | Replace with one strong static image or a short list | CSS scroll-snap row (no JS); a small carousel island (Embla, Swiper) if the owner insists | Sliders are slow and rarely clicked beyond slide 1. Show the owner what the slider contains first; often it is 3 to 5 images worth a grid. |
| **Gallery / lightbox** | Image grid with Astro's `<Image>` and a lightweight lightbox (PhotoSwipe, or a native `<dialog>`) | Grid without lightbox | Download originals, not the theme's crops. Keep alt texts. |
| **Video embeds** (YouTube, Vimeo) | Click-to-load facade (`astro-embed`'s YouTube/Vimeo components or lite-youtube): shows a thumbnail, loads the player only on click | Plain link with thumbnail | Facades avoid loading third-party cookies before a click, which helps with GDPR. |
| **Maps** (Google Maps plugins, iframes) | Static map image plus an "Open in Google Maps / OpenStreetMap" link | Click-to-load embed; OpenStreetMap iframe | A live Google map loads Google services on page view; the static version doesn't. |
| **Google Fonts** | Self-host via Fontsource packages | Download the font files into `public/fonts` | Loading fonts from Google's servers was ruled a GDPR violation in Germany (LG München 2022); self-hosting removes the issue. |
| **File downloads** (PDF, DOCX) | Copy to `public/files/…`, keep the old path if it was linked externally | Redirect old file URLs | `download-assets.mjs` handles them like images. |
| **Archives, categories, tags, pagination, "latest posts" widgets** | Generated by Astro at build time from the content collections | Drop tag archives nobody uses | Only build archive pages that had visitors or are in the navigation. |
| **RSS feed** | `@astrojs/rss` | Drop if unused | Keep the old feed URL if people subscribe. |
| **Sitemap, robots.txt** | `@astrojs/sitemap`, `public/robots.txt` | – | Set `site` in astro.config. |
| **Self-hosted video** (header videos, product films) | YouTube or Vimeo with a click-to-load facade; or re-encode (a 1080p header loop rarely needs more than 5–10 MB) | Object storage / video service for large files | Hosts limit file sizes (Cloudflare: 25 MiB per file) and git gets heavy; the inventory lists video files with their size. Leave very large files on the old server only until go-live. |
| **Share buttons** (AddToAny, Shariff, Social Warfare) | Check they are visible at all (often `display:none`); if yes, plain share links without scripts | Drop them | Third-party share scripts load trackers. |
| **Counters and "live" statistics** (count-up numbers, odometers) | Fixed numbers someone updates once a year, from the owner | A small count-up animation on the real figures | The old values are computed by scripts (sometimes prorated by day of year); a capture records a moment, not facts. `snapshot.mjs --content` lists them. |
| **FAQ / accordion** blocks | `<details>`/`<summary>`, no script | – | Accessible by default. |
| **Icon fonts** (Font Awesome, Elegant Icons) | SVG icon files imported as components (e.g. Lucide, or the same icon set as SVG; astro-setup.md §9) | Keep the font, self-hosted | Icon fonts are heavy and inaccessible. |

## Needs a small service

| Feature | Recommended | Alternatives | Notes |
|---|---|---|---|
| **Contact and enquiry forms** (Contact Form 7, Gravity Forms, WPForms, Elementor form, TYPO3 powermail) | **Drop the form.** Show the e-mail address and phone number prominently as links (`mailto:`, `tel:`); for enquiries, a `mailto:` link with a prefilled subject plus a short line on what to include ("route, goods, preferred dates") | Only if the form is central to the business (many enquiries a week, structured data someone processes): a form backend service that e-mails the owner (Formspree, Web3Forms, Basin and similar; compare free tiers and where data is stored, EU options exist), Netlify Forms on Netlify, or a small Cloudflare Worker with an e-mail API | Tell the owner what a form costs: a sending service (often paid above a free tier), spam protection (honeypot, captcha or Cloudflare Turnstile), a privacy-policy entry, an end-to-end test before go-live, and someone noticing when it silently stops delivering. An e-mail link needs none of that, works on every device, and the enquiry lands in the mailbox they already read. |
| **Application forms with file uploads** (jobs) | An e-mail address for applications, or a link to the job platform they already use | A hosted application tool | Uploads make forms much harder (file storage, size limits, data protection for CVs). |
| **Newsletter sign-up** (Mailchimp, Brevo, CleverReach) | Keep the provider; use its embedded form or hosted sign-up page | – | Nothing to migrate except the form. |
| **Site search** (details: search.md) | Pagefind: builds a search index at build time, runs entirely in the browser, no server, no account | Drop search on small sites (under ~30 pages) and rely on good navigation | Pagefind integrates with Astro via the `astro-pagefind` package or a post-build step. Check that a search field is actually visible; search plugins are often installed but not placed anywhere. |
| **Booking / appointments** (Calendly, Bookly, Amelia, Doctolib) | Keep the external service; link or embed it | – | Plugin-based booking inside WordPress (Bookly, Amelia) has data in WordPress: export it and move to a hosted booking tool first. |
| **Analytics** (Google Analytics, Tag Manager, Matomo, Meta Pixel) | Ask whether anyone looks at the numbers. If yes: a cookieless option (Cloudflare Web Analytics, Plausible, Matomo without cookies) | Keep Google Analytics with consent banner | Cookieless analytics may remove the need for a cookie banner entirely; see privacy-and-legal.md. |

## Usually dropped

| Feature | Recommended | Alternatives | Notes |
|---|---|---|---|
| **Comments** | Turn off; keep existing comments as static text under the posts if they matter | Giscus (needs a GitHub account for commenters, rarely fits non-tech audiences); a hosted comment service | Most small-business sites have no real comments, only spam. |
| **Social media feeds** (Instagram feed, Smash Balloon, Elfsight) | Replace with a link/button to the profile | A build-time fetch with the platform's API (tokens expire; fragile) | Feeds break often and load third-party scripts. |
| **Cookie banner** (Borlabs, Complianz, Cookiebot, Real Cookie Banner) | Remove if no tracking and no third-party embeds load before consent remain | Keep a lightweight consent tool if tracking stays | Decide from the privacy capture and the list of remaining third parties: privacy-and-legal.md. |
| **Captchas** (reCAPTCHA, hCaptcha, ALTCHA, Friendly Captcha, agency-hosted ones) | Go away with the form plugin; use the form service's protection | Cloudflare Turnstile | Agency-hosted captchas often load from the agency's server: one more third party gone. |
| **Consent-log extensions** (cookies like `*_consent_id`) | Go away with the consent tool | – | Only needed while a consent tool stays. |

## Not static: keep as a separate service

| Feature | Recommended | Alternatives | Notes |
|---|---|---|---|
| **Shop** (WooCommerce, Shopify embeds) | Few products: payment links (e.g. Stripe Payment Links) or a cart overlay service (Snipcart). Real shop with stock and accounts: keep a hosted shop (Shopify, or the existing WooCommerce moved to a subdomain like shop.example.com) | – | Migrating a shop is its own project. Say so clearly. |
| **Member area / logins** | Keep separately (subdomain) or use a hosted platform | Small internal group: host-level access control (Cloudflare Access, Netlify password protection) | – |
| **Password-protected pages** | Host-level protection (Cloudflare Access, Netlify, basic auth on a web space) | Drop the protection if it is no longer needed | WordPress page passwords don't carry over. |

## Structural

| Situation | Approach |
|---|---|
| **Page builders** (Elementor, Divi, WPBakery, GoodLayers, Avada, Bricks) | Their layouts are not content; rebuild them as Astro components. Take text and images from the rendered pages. Give repeating layouts (team grid, project grid) a content collection instead of hand-coded pages. |
| **Multilingual** (WPML, Polylang, TranslatePress, Weglot, GTranslate, TYPO3 languages) | Find out first which kind (stored translations, translation service, live machine translation, mixed-language pages): multilingual.md. Then Astro's i18n routing with one folder per language and the old URL scheme. |
| **Events** (The Events Calendar, tx_news events) | Content collection with dates; upcoming/past split at build time. Add a scheduled daily CI build so past events drop off automatically. |
| **Forms with file upload** | Form services with upload support exist but cost more; otherwise ask senders to e-mail attachments. |
| **Custom post types without REST access** | Take them from the rendered pages (inventory "URL groups", `.migration/urls-<type>.txt`); each becomes a content collection. |
| **Plugins installed but unused** | The inventory lists them separately. Nothing to migrate; mention in the report that they go away. |
